# Audio Switch Pro 2.0.0

Плагин **StreamDock для Windows**. Этот пакет не является установщиком Elgato Stream Deck.

## Установка готового пакета

1. Полностью закройте StreamDock через значок в системном трее.
2. Распакуйте **AudioSwitch-2.0.0-StreamDock.zip** в обычную папку.
3. Запустите `Install-StreamDock.bat` без прав администратора.
4. Откройте StreamDock. В действии **Audio Switch** добавьте устройства в нужном порядке.

Например: **маленькие динамики → большие динамики → наушники → маленькие динамики**.
Имена Windows можно заменить короткими подписями на кнопке. Кнопки ↑ / ↓ изменяют порядок.
Старые настройки `device1` / `device2` читаются автоматически; UUID действий сохранены.

Установщик проверяет комплектность, SHA-256 файлов и запуск комплектного Windows-модуля.
Предыдущую папку плагина сохраняет в `%APPDATA%\HotSpot\StreamDock\AudioSwitch-backups\`.
Профили StreamDock установщик не удаляет. Перед обновлением полезно экспортировать профиль.
Скачивать Node.js, npm, NirCmd или компилировать C# конечному пользователю не требуется.
Сам StreamDock должен быть установлен заранее.

Ручная установка: скопируйте **целую** папку `com.lizard.switchaudio.sdPlugin` в
`%APPDATA%\HotSpot\StreamDock\plugins\`, заменяя предыдущую папку после её резервного копирования.
Не создавайте двойную вложенность `.sdPlugin/.sdPlugin`.
Если политика организации запрещает PowerShell, используйте ручную установку, а не обход корпоративной политики.

## Возможности

- Список до 32 устройств, цикл вперёд/назад либо включение первого устройства одной кнопкой.
- Проверка фактического устройства Windows перед переключением, а не счётчик прошлых нажатий.
- Пропуск отключённых устройств; строгий режим с ошибкой вместо пропуска.
- Выбор ролей: все, обычный звук (Console + Multimedia), только связь (Communications).
- Короткие подписи и иконки; индикация текущего устройства обновляется примерно раз в 2 секунды.
- Выходы и входы, раздельные списки в настройке, сохранение отсутствующих устройств в конфигурации.
- Mute, системная громкость с настраиваемым шагом, установка 0–100%, громкость приложения по имени процесса.
- Медиа-кнопки без настройки: Play/Pause, следующий и предыдущий трек управляют тем, что реально играет.
- Push-to-Talk: удержание включает выбранный в этот момент микрофон, отпускание глушит именно его.

## Ограничения совместимости — важно

Целевая среда: Windows 10/11, StreamDock **3.10.188.226 или новее** со встроенным Node.js 20,
.NET Framework 4.x и исправная служба Windows Audio. Пакет не требует администраторских прав.
Windows ARM, Mac, Linux, Elgato Stream Deck и все сторонние ребрендинги устройств не сертифицированы.
Требование версии StreamDock взято из SDK производителя; отдельный установленный системный Node.js не нужен.

«Просто установить» означает установить плагин, затем **один раз выбрать устройства на данном ПК**.
Windows endpoint ID принадлежат конкретной установке ОС: экспортированный чужой профиль требует перенастройки.
Переустановка драйвера, Bluetooth-переподключение в другом режиме или перенос USB иногда меняют ID.
Два устройства с одинаковыми именами различаются по ID; совпадение названия не используется как небезопасная подмена.

Приложения, в которых выбран конкретный выход вместо «По умолчанию», ASIO/эксклюзивные потоки,
некоторые игры и коммуникационные приложения могут потребовать собственной настройки или перезапуска потока.
Плагин не перенаправляет принудительно каждое приложение. Аппаратные профили Bluetooth не переключает.
IPolicyConfig для смены default endpoint — недокументированный интерфейс Windows: вечную совместимость обещать нельзя.

Push-to-Talk зависит от событий `keyDown` и `keyUp` конкретного устройства. Это не аппаратная защита приватности.
До первого нажатия состояние микрофона не меняется автоматически. После отпускания он будет выключен.
При исчезновении кнопки, отключении устройства, потере связи с хостом и штатном завершении выполняется очистка.
При аварийном завершении процесса, отключении питания или невозможности обратиться к Windows Audio гарантировать mute нельзя.
Одна кнопка PTT не должна использоваться как единственный барьер для конфиденциального разговора.

Медиа-кнопки работают через Windows System Media Transport Controls (SMTC): управление получает приложение,
которое сейчас играет, включая UWP-приложения вроде Яндекс.Музыки. Никаких путей, имён процессов и URI задавать не нужно.
На кнопке Play/Pause отображается название трека, в её инспекторе — живая карточка «трек / исполнитель / приложение».
Если ничего не играет, Play/Pause заново открывает последнее музыкальное приложение, замеченное в этой сессии StreamDock,
и повторяет команду. Приложение без медиа-контролов выдаёт явную ошибку вместо слепых клавиатурных нажатий.

Если антивирус поместил `AudioSwitch.exe` в карантин, плагин показывает понятное сообщение вместо ENOENT.
Установщик откатывает установку, если модуль исчезает во время копирования. Восстановите файл из
«Защита от вирусов и угроз → Журнал защиты» или самостоятельно добавьте исключение для папки плагина;
установщик никогда не меняет настройки антивируса сам.
Именованный процесс без аудиосессии (громкость приложения) по-прежнему выдаёт ошибку; чужое приложение не изменяется.

## Проверки и воспроизводимая сборка

В исходниках: `tests/audio.test.js`, нативный `AudioSwitch.exe selftest`, Windows CI,
проверка всех путей манифеста и самостоятельный комплектный ZIP. Эти проверки **не заменяют** испытание физического
StreamDock и аудиоустройств на Windows 10/11. До такого прогона это кандидат на аппаратную проверку, а не сертифицированный универсальный релиз.

Разработчику нужны Windows, Node.js 20+ с npm, Python 3 и компилятор .NET Framework. Запустите `prepare-release.bat`.
Он использует `npm ci`, собирает модуль через `tools/build-native.py`, выполняет тесты и создаёт пакет в `dist/`.
`install.bat` в исходниках — прежняя совместимая точка входа в **сборку**, не установщик готового пакета.

Проверка целостности готового ZIP: распаковать и выполнить
`powershell -NoProfile -File .\Install-StreamDock.ps1 -ValidateOnly`.
Контрольные суммы обнаруживают повреждение файлов, но не являются цифровой подписью издателя.

## Ручной приёмочный прогон

Проверьте цикл трёх выходов; смену default вручную в Windows; отключение и возврат наушников;
повторный запуск StreamDock; обновление старого профиля; отдельные роли связи; одинаковые имена устройств;
кириллицу в названии и пути; быстрое нажатие; регулировку громкости 0/100%; явное имя приложения без сессии;
PTT press/release, смену микрофона во время удержания и закрытие хоста.
Медиа: Play/Pause/Next/Previous в Яндекс.Музыке и обычном плеере, название трека на кнопке,
повторный запуск последнего приложения при пустой сессии, ошибка для приложения без SMTC.
Для проверки переносимости нужен чистый ПК/пользователь без Node/npm/NirCmd и с подходящим StreamDock.
